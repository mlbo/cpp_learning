## 📚 Day 1: 两数之和 - 形象化讲解

### 🎮 题目理解（生活类比）

想象你在超市购物，手里有一张购物清单：

```
物品价格: [2元, 7元, 11元, 15元]
你的预算: 9元

问题: 找出哪两样东西正好花完你的预算？
```

**答案**: 2元的 + 7元的 = 9元，正好！

---

### 🧠 方法一：暴力法（最容易理解）

#### 形象比喻：排队配对

想象你是班长，要让班里每两个同学配对：

```
同学编号: [0号, 1号, 2号, 3号]
价值:     [2元, 7元, 11元, 15元]

配对过程:
1. 先让0号同学(2元)尝试配对:
   - 0号 + 1号 = 2+7 = 9元 ✓ 成功！找到答案！

如果第一个不行，继续尝试:
   - 0号 + 2号 = 2+11 = 13元 ✗ 不等于9
   - 0号 + 3号 = 2+15 = 17元 ✗ 不等于9

2. 然后让1号同学尝试配对后面的...
```

#### 动画演示

```
第1轮配对:
[2, 7, 11, 15]   target = 9
 ↑  ↑
 i  j
 2 + 7 = 9 ✓ 找到！

如果没有找到，继续:
[2, 7, 11, 15]
 ↑      ↑
 i      j
 2 + 11 = 13 ✗

[2, 7, 11, 15]
 ↑          ↑
 i          j
 2 + 15 = 17 ✗

...以此类推
```

#### 时间复杂度解释

```
假设有 n 个数:
- 第1个数需要和后面 n-1 个数配对
- 第2个数需要和后面 n-2 个数配对
- ...
- 总共需要: (n-1) + (n-2) + ... + 1 ≈ n²/2 次

用大O表示: O(n²) ← 这就是"平方时间复杂度"
```

### 🚀 方法二：哈希表法（推荐！）

#### 核心思想：逆向思维

**传统思维**：遍历每一个数，找另一个数和它凑成target

**逆向思维**：对于每个数，直接问"你的另一半在哪里？"

#### 形象比喻：失物招领处

```
假设 target = 9

失物招领处的登记册:
┌────────────────────────────────┐
│  已出现的金额 2 元 -> 0 号同学    │
└────────────────────────────────┘

遍历过程:
1. 来到2号同学(值=2)，想找7元
   → 查登记册: 7元出现过吗？没有
   → 登记: "2元由0号同学持有"
   
2. 来到7号同学(值=7)，想找2元
   → 查登记册: 2元出现过吗？有！
   → 找到配对！返回[0, 1]
```

#### 哈希表内部结构

```
哈希表就像一个超快的字典:

┌───────────┬───────────┐
│   Key     │   Value   │
│  (值)     │  (索引)   │
├───────────┼───────────┤
│    2      │    0      │  ← nums[0]=2 存入
│    7      │    1      │  ← nums[1]=7 存入时发现
│           │           │     target-7=2 已存在！
└───────────┴───────────┘

平均查找速度: O(1) ← 通常只需很少的桶访问；严重冲突时可能退化
```

#### 代码执行过程图解

```
nums = [2, 7, 11, 15], target = 9

补数应在更宽的整数类型中计算，避免 `target - nums[i]` 在 `int` 边界溢出。

Step 1: i=0, nums[i]=2
┌─────────────────────────────────────┐
│ complement = target - 2 = 7         │
│ 在哈希表中查找7... 找不到           │
│ 存入: map = {2 → 0}                │
└─────────────────────────────────────┘

Step 2: i=1, nums[i]=7
┌─────────────────────────────────────┐
│ complement = target - 7 = 2         │
│ 在哈希表中查找2... 找到了！         │
│ 返回: [map[2], i] = [0, 1]         │
└─────────────────────────────────────┘
```

#### 时间复杂度对比

```
方法对比:

暴力法: 
  遍历O(n) × 每次查找O(n) = O(n²)
  
哈希表法:
  遍历O(n) × 平均查找O(1) = 平均O(n)

举例说明:
  如果有10000个数:
  - 暴力法: 需要约 50,000,000 次操作
  - 哈希表: 理想分布下工作量与 10,000 同阶
  
  实际倍数取决于哈希质量、装载因子、缓存和机器，不能由大 O 直接给出固定倍数。
```

## 📚 Day 2: 原地覆盖 - 把“读区”和“写区”分开

以删除重复项为例，数组可以画成三段：

```
[ 已确认答案 | 已处理但可覆盖 | 尚未读取 ]
 0          slow            fast          n
```

`fast` 只负责读取，`slow` 表示答案边界。每轮开始前先问两句：`fast` 前面的元素是否都检查过？下一次写入会不会覆盖还没读的数据？

```
输入: [1, 1, 2, 2, 3]

初始: [1 | 1, 2, 2, 3]
       s   f

1 == 1：只移动 fast
       [1 | 1, 2, 2, 3]
       s      f

2 != 1：先扩展答案区，再写入
       [1, 2 | 2, 2, 3]
          s     f
```

这里的关键不是变量名，而是不变量：答案区保存“已读输入去重后的稳定结果”。完整契约与递归教学变体见 [LeetCode 26 题解](day_02/code/leetcode/0026_remove_duplicates/README.md)。

## 📚 Day 3: 逆向合并 - 从不会覆盖输入的一端写

`nums1` 尾部有预留空间时，从前写可能踩掉尚未比较的旧元素；从后写则先放当前最大值：

```
nums1: [1, 2, 3, _, _, _]
                p1       out
nums2: [2, 5, 6]
                p2

比较 3 与 6，把 6 放到 out-1：
nums1: [1, 2, 3, _, _, 6]

比较 3 与 5，把 5 放到新的 out-1：
nums1: [1, 2, 3, _, 5, 6]
```

每轮后，右侧后缀已经是最终答案；左侧两个半开区间仍保存未处理输入。完整边界验证和代码见 [LeetCode 88 题解](day_03/code/leetcode/0088_merge_sorted_array/README.md)。

移动零则使用正向稳定分区：`[0, slow)` 保存按原顺序出现的非零元素，`[slow, fast)` 保存零。两题方向不同，但判断标准相同：写入不能破坏尚未读取的数据；详见 [LeetCode 283 题解](day_03/code/leetcode/0283_move_zeroes/README.md)。

## 📚 Day 4: 对撞指针 - 一次移动要排除一整批候选

盛水容器中，面积由较矮边限制：

```
height: [1, 8, 6, 2, 5, 4, 8, 3, 7]
             L                    R

area = min(height[L], height[R]) * (R - L)
```

若左边更矮，固定左边再把右边向内移动，只会让宽度变小，容器高度又不可能超过这根左边。因此当前左边不可能产生更优答案，可以安全排除；移动较高边则没有同样证明。完整排除证明见 [LeetCode 11 题解](day_04/code/leetcode/0011_container_with_most_water/README.md)。

三数之和先排序，再固定第一个数，把剩余问题变成有序两数之和：

```
[-4, -1, -1, 0, 1, 2]
      i   L           R

sum < 0 -> L 右移
sum > 0 -> R 左移
sum = 0 -> 记录后跳过相邻重复值
```

排序既提供移动方向，也让去重值相邻；和必须在更宽整数类型中计算。完整去重层次与复杂度见 [LeetCode 15 题解](day_04/code/leetcode/0015_3sum/README.md)。

## 📚 Day 5: 滑动窗口 - 先判断是“最短满足”还是“最长合法”

两类窗口不能共用同一个答案更新位置：

```
最短满足: 加入右端 -> 满足时记录 -> 移除左端继续缩短
最长合法: 加入右端 -> 非法时移除左端 -> 恢复合法后记录
```

以 `target = 7, nums = [2,3,1,2,4,3]` 为例：

```
[2,3,1,2] sum=8  -> 记录长度4，移除2后 sum=6
  [3,1,2,4] sum=10 -> 依次记录4、3，再收缩
        [4,3] sum=7 -> 记录长度2
```

正数前提让“右移时和不减、左移时和不增”成立；若有负数，原移动规则可能漏解。完整证明见 [LeetCode 209 题解](day_05/code/leetcode/0209_minimum_size_subarray_sum/README.md)，最长合法窗口见 [LeetCode 3 题解](day_05/code/leetcode/0003_longest_substring/README.md)。

## 📚 Day 6: 二分查找 - 每轮都要写出仍可能有答案的区间

本周统一使用半开区间 `[left, right)`：

```
[ 已排除：都 < target | 仍待判定 | 已确认：都 >= target ]
0                    left      right                       n
```

查左边界时：

- `nums[mid] < target`：`mid` 不可能是答案，令 `left = mid + 1`。
- `nums[mid] >= target`：`mid` 仍可能是第一个候选，令 `right = mid`。

每轮区间都严格缩小，终止时 `left == right`，未知区间为空。标准查找见 [LeetCode 704 题解](day_06/code/leetcode/0704_binary_search/README.md)，左右边界见 [LeetCode 34 题解](day_06/code/leetcode/0034_find_first_and_last/README.md)。

## 💡 学习技巧总结

### 对于算法小白

1. **先理解题意**
   - 用生活场景类比
   - 画出具体例子
   - 手动模拟过程

2. **从暴力开始**
   - 先用最直观的方法
   - 确保理解问题
   - 再考虑优化

3. **画图是关键**
   - 数据结构画图
   - 执行过程画图
   - 边界情况画图

4. **多写多练**
   - 敲代码不是抄代码
   - 理解每一行的作用
   - 尝试修改和扩展

### 复杂度速记

```
O(1): 一次就搞定（如数组访问）
O(log n): 对数时间（如二分查找）
O(n): 遍历一遍（如线性查找）
O(n log n): 许多比较排序的典型/最坏量级（如归并排序）
O(n²): 双层循环（如冒泡排序）

从小到大: 1 < log n < n < n log n < n²
```
