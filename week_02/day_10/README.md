## 一、weak_ptr 详解

### 1.1 weak_ptr 的设计目的

`weak_ptr` 是一种不控制对象生命周期的智能指针，它指向一个由 `shared_ptr` 管理的对象。

更精确地说，`weak_ptr` 关联的是同一个**控制块**，并借此观察对象是否仍存在；它本身不让对象继续存活，也不能直接解引用。

**核心特点：**
- 不增加强引用计数，但会让控制块保留弱观察状态
- 不影响对象的生命周期
- 需要通过 `lock()` 转换为 `shared_ptr` 才能访问对象

### 1.2 为什么需要 weak_ptr？

```cpp
// 场景1：循环引用问题
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;  // 导致循环引用
};

// 场景2：观察者模式
class Subject {
    std::vector<std::weak_ptr<Observer>> observers;  // 不控制观察者生命周期
};
```

### 1.3 weak_ptr 核心操作

| 方法 | 说明 |
|------|------|
| `lock()` | 返回 shared_ptr，若对象已销毁则返回空 |
| `expired()` | 检查对象是否已销毁 |
| `use_count()` | 返回共享对象的 shared_ptr 数量 |
| `reset()` | 释放引用 |

### 1.4 lock() 方法详解

```cpp
std::weak_ptr<int> wp = sp;
if (auto sp2 = wp.lock()) {  // 安全获取
    // sp2 有效，可以使用
    *sp2 = 42;
} else {
    // 对象已被销毁
}
```

不要先 `if (!wp.expired())` 再单独 `wp.lock()`：两次操作之间，最后一个 `shared_ptr` 可能在另一个线程销毁，形成检查后失效竞态。一次 `lock()` 会原子地完成“检查并在仍存活时取得共享所有权”，得到的局部 `shared_ptr` 在其作用域内保证对象不被销毁。

## 二、循环引用与解决方案

先画对象图，并区分两种边：

```
owner ── owning edge(shared_ptr) ──> child
child ── observing edge(weak_ptr) ─> owner
```

只有强拥有边会增加强引用计数。所谓循环引用泄漏，不是“两个对象互相能访问”就会发生，而是**强拥有边形成闭环**，使环内每个对象即使失去外部所有者，强计数仍无法归零。父子关系、观察者、缓存等模型中，反向边或纯观察边通常应为弱边。

### 2.1 循环引用问题

```
┌─────────┐         ┌─────────┐
│ Node A  │────────>│ Node B  │
│ ref:1   │         │ ref:1   │
│<────────│         │<────────│
└─────────┘         └─────────┘
    ↑                    │
    │    循环引用         │
    └────────────────────┘
```

### 2.2 解决方案：使用 weak_ptr

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 改为 weak_ptr
};
```

## 三、EMC++ Item 20：shared_ptr 可能悬空时使用 weak_ptr

> **条款要点：** 当对象可能已经销毁、但你仍需要保留一个可检测的非拥有观察句柄时，使用 `weak_ptr`。

**典型应用场景：**
1. 缓存系统 - 不阻止缓存对象被释放
2. 观察者模式 - Subject 不拥有 Observer
3. 打破循环引用 - 解决 shared_ptr 循环依赖
4. 对象池 - 允许对象被正常回收

**使用模式：**
```cpp
if (auto sp = wp.lock()) {
    // 安全使用 sp
} else {
    // 对象已销毁
}
```

`weak_ptr` 不是普通裸指针的无脑替代品：它必须配合 `shared_ptr` 控制块工作，并承担控制块与原子操作成本。如果借用者的生命期严格嵌套在所有者内部，`T&`/`T*` 往往已经足够；如果必须延长生命期，就应取得 `shared_ptr`。

## 四、EMC++ Item 21：优先使用 make_unique 和 make_shared

make 函数把“分配对象”和“立即交给智能指针”合成一个表达式，通常更清晰，也避免裸 `new` 在复杂表达式中的异常安全风险。

```cpp
auto unique = std::make_unique<Widget>(42);
auto shared = std::make_shared<Widget>(42);
```

`make_shared` 往往把对象与控制块合并为一次分配，具有更好的局部性；但“优先”不等于“永远”：

- 需要为 `shared_ptr` 指定自定义删除器时，不能用 `make_shared` 直接表达。
- 合并分配时，即使强计数归零、对象已经析构，只要还有 `weak_ptr`，包含对象存储空间的整块分配通常仍不能释放。
- 私有构造函数、类专用 `operator new`、特殊内存池或分配策略可能要求直接构造。
- `make_unique` 自 C++14 提供；C++11 项目需要自行封装或显式构造，但仍应避免让裸指针在语句间游离。

## 五、LeetCode 题目精讲

### 4.1 LeetCode 142: 环形链表 II

**题目：** 给定链表头节点，返回链表开始入环的第一个节点。

**快慢指针数学推导：**

```
设：
- a: 头到入环点的距离
- b: 入环点到相遇点的距离
- c: 相遇点到入环点的距离

快指针走的距离：a + b + k(b+c)
慢指针走的距离：a + b

快指针是慢指针的两倍：
2(a + b) = a + b + k(b+c)
=> a + b = k(b+c)
=> a = (k-1)(b+c) + c

结论：从相遇点和头同时出发，会在入环点相遇！
```

**算法步骤：**
1. 快指针走两步，慢指针走一步
2. 相遇后，一个指针回起点
3. 两指针各走一步，相遇点即为入口

推导中 `b+c` 是环长。等式说明“头到入口的距离 `a`”等于“相遇点到入口的距离 `c`”再加若干整圈，所以两个指针以相同速度前进时会在入口第一次重合。`k` 是快指针在相遇前比慢指针多绕的圈数，不需要在代码中求出。

**时间复杂度：** O(n)  
**空间复杂度：** O(1)

### 4.2 LeetCode 19: 删除链表的倒数第N个节点

**双指针技巧：**
1. 从 `dummy` 出发，让快指针先走 n 步，使快慢之间保持 n 条边的间距
2. 快慢指针同时移动，直到快指针到达最后一个节点
3. 慢指针指向要删除节点的前一个节点

**可视化演示：**
```
链表: 1->2->3->4->5, n=2

初始:     dummy->1->2->3->4->5
          slow  fast

快指针走2步: dummy->1->2->3->4->5
                    slow    fast

同时移动:   dummy->1->2->3->4->5
                          slow  fast

slow在倒数第3个节点，删除slow->next
```

虚拟头节点保证“删除原头节点”也有前驱。工程接口还必须决定非法输入：当 `n <= 0` 或 `n` 大于链表长度时，是原样返回、抛异常还是报告错误；LeetCode 保证输入合法，但教程实现会显式保护边界，避免空指针解引用。

**时间复杂度：** O(n) 一次遍历  
**空间复杂度：** O(1)
