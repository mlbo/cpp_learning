## 链表常见技巧汇总

### 1. 双指针技巧

| 技巧 | 应用场景 | 时间复杂度 |
|------|----------|------------|
| 快慢指针 | 找中点、检测环 | O(n) |
| 前后指针 | 删除倒数第k个节点 | O(n) |
| 交叉指针 | 找相交节点 | O(n+m) |

### 2. 虚拟头节点

```cpp
ListNode dummy(0);
dummy.next = head;
// 处理头节点删除等边界情况
return dummy.next;
```

**优点**：统一处理头节点边界情况，代码更简洁

### 3. 递归 vs 迭代

| 方式 | 优点 | 缺点 |
|------|------|------|
| 递归 | 代码常能直接表达子问题 | 额外空间取决于递归深度，不能一律写成 O(n) |
| 迭代 | 容易把辅助空间控制为 O(1) | 状态和改链边界通常更复杂 |

例如递归反转链表的深度是 `n`，调用栈为 `O(n)`；自顶向下归并每次把规模减半，最大深度是 `log n`，调用栈为 `O(log n)`。

### 4. 从题目特征识别工具

| 题目特征 | 优先想到 |
|---------|---------|
| 头节点可能被删除、替换或需要统一边界 | 哨兵节点 |
| 中点、环、倒数距离 | 快慢指针或前后指针 |
| 两条链表走完不同前缀后对齐 | 交叉指针 |
| 链表排序且要求 `O(n log n)` | 归并排序 |
| 连续反转一段节点 | 先保存后继，再断开和重连 |

## LeetCode 题目详解

### 160. 相交链表

**题目**：给你两个单链表的头节点 `headA` 和 `headB`，找出并返回两个单链表相交的起始节点。

这里的“相交”是两个指针最终指向**同一个节点地址**，不是两个节点的 `val` 恰好相等。两条完全独立但值序列相同的链表仍然不相交，测试也必须比较返回指针与预期节点地址。

**核心思路**：双指针交叉遍历
- 指针A遍历完链表A后，跳到链表B继续
- 指针B遍历完链表B后，跳到链表A继续
- 两指针最终会在相交点相遇（或同时到达末尾nullptr）

**关键公式**：
```
a + c + b = b + c + a
```
其中 a、b 是各自独立部分长度，c 是公共部分长度。

### 148. 排序链表

**题目**：给你链表的头节点 `head`，将其按升序排列并返回排序后的链表。

**进阶要求**：O(n log n) 时间复杂度 + O(1) 额外辅助空间

**核心思路**：归并排序
1. **找中点**：快慢指针找到链表中点
2. **分割**：从中间断开，递归排序两部分（自顶向下版本）
3. **合并**：合并两个有序链表

**为什么选择归并排序？**
- 常见数组快速排序依赖随机访问；链表也能设计分区版快速排序，但指针分区复杂、稳定性差且仍有最坏 O(n²) 风险
- 基于数组堆的堆排序同样依赖高效下标定位，不适合直接套到单链表
- 归并排序只需顺序拆分和线性合并，天然适合链表
- 自顶向下版本时间 `O(n log n)`、递归栈 `O(log n)`
- 自底向上版本按长度 `1, 2, 4, 8...` 合并，时间 `O(n log n)`、额外辅助空间 `O(1)`

因此，不能一边声称“要求 O(1) 空间”，一边只讲递归版却不说明调用栈。递归版更适合先理解分治；真正对应常数额外空间进阶要求的是自底向上版。

### 五句复盘

1. 头节点可能被删除、替换或需要统一前驱接口时，哨兵节点能减少边界分支。
2. 相交链表比较的是节点地址，交叉指针通过让两条路径都走 `a + b + c` 消除独立前缀的长度差。
3. 自顶向下与自底向上归并都为 `O(n log n)` 时间，额外空间分别是 `O(log n)` 调用栈与 `O(1)` 辅助状态。
4. 删除倒数第 `n` 个节点必须把 `n <= 0` 和 `n` 超长定义为前置条件违例或明确失败结果，不能解引用越界指针。
5. 每次修改 `next` 前先保存后继，才能在提交改链后继续到达未处理后缀并验证结构没有丢失节点。
