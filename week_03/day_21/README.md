### C++11特性：Lambda表达式

```cpp
// 基本语法
[capture](params) -> return_type { body }

// 捕获方式
[x]      // 值捕获
[&x]     // 引用捕获
[=]      // 对Lambda体内实际使用且可捕获的自动变量隐式值捕获（不推荐）
[&]      // 对Lambda体内实际使用且可捕获的自动变量隐式引用捕获（不推荐）
[=, &x]  // 混合捕获

// C++14泛型Lambda
auto add = [](auto a, auto b) { return a + b; };

// C++14初始化捕获
auto f = [p = std::move(ptr)]() { };
```

默认捕获不会把作用域里所有实体都塞进闭包：未在 Lambda 体内使用的局部变量不会被捕获，全局和静态对象也不是捕获成员。C++17 中通过成员名访问对象状态通常意味着捕获 `this` 指针，因此 `[=]` 也不等于复制整个对象；长期保存闭包时仍应显式写出依赖并检查生命周期。

### 讲解题：LC 155. 最小栈

#### 题目链接

[LeetCode 155](https://leetcode.cn/problems/min-stack/)

#### 题目描述

设计一个支持 push，pop，top 操作，并能在常数时间内检索到最小元素的栈。

#### 形象化理解

想象一个"智能书堆"，不仅能正常放书取书，还能随时告诉你当前最薄的书：

```
操作序列：
push(-2) → 栈:[-2], 最小:-2
push(0)  → 栈:[-2, 0], 最小:-2
push(-3) → 栈:[-2, 0, -3], 最小:-3
getMin() → -3
pop()    → 栈:[-2, 0], 最小:-2
top()    → 0
getMin() → -2
```

#### 解题思路

使用**辅助栈**同步记录每个状态下的最小值：

```mermaid
graph LR
    subgraph "数据栈"
    A1[-2] --> A2[0]
    A2 --> A3[-3]
    end
    
    subgraph "最小栈"
    B1[-2] --> B2[-2]
    B2 --> B3[-3]
    end
```

#### 代码实现

```cpp
class MinStack {
private:
    stack<int> dataStack;
    stack<int> minStack;
    
public:
    void push(int x) {
        dataStack.push(x);
        if (minStack.empty() || x <= minStack.top()) {
            minStack.push(x);
        } else {
            minStack.push(minStack.top());
        }
    }
    
    void pop() {
        dataStack.pop();
        minStack.pop();
    }
    
    int top() {
        return dataStack.top();
    }
    
    int getMin() {
        return minStack.top();
    }
};
```

数据结构接口只负责维护 `push/pop/top/getMin/empty` 的状态与复杂度，不应该在这些成员中读取命令、打印菜单或决定业务操作顺序。业务流程负责把“push -2、查询最小值、处理空栈错误”组织成用户场景。教程实现把空栈 `pop/top/getMin` 定义为抛出 `std::underflow_error`，并由调用者决定记录日志、重试还是终止；链表节点由析构函数统一释放，避免把资源管理责任泄漏给业务层。

一旦类手写析构函数释放裸指针链表，编译器生成的默认复制只会复制 `head` 指针，两个对象随后会重复释放同一串节点；这就是“拥有资源的类必须一起设计析构、复制和移动策略”的原因。本日暂不展开深拷贝和移动接管，选择最清楚的策略：复制构造、复制赋值、移动构造、移动赋值全部 `= delete`。测试用 `static_assert` 锁定这项类型契约，后续学习 Rule of Five 后再实现安全的值语义。

### 实战题：LC 150. 逆波兰表达式求值

#### 题目链接

[LeetCode 150](https://leetcode.cn/problems/evaluate-reverse-polish-notation/)

#### 提示

1. 使用栈存储操作数
2. 遇到运算符时弹出两个操作数计算
3. 结果压回栈中
4. 注意操作数的顺序（先弹出的是右操作数）

#### 题目描述

根据逆波兰表示法（后缀表达式），求表达式的值。

#### 形象化理解

逆波兰表达式就是"操作数在前，运算符在后"：

```
中缀表达式: (2 + 3) * 4
后缀表达式: 2 3 + 4 *

计算过程：
  读入2 → 栈:[2]
  读入3 → 栈:[2, 3]
  读入+ → 弹出3和2，计算2+3=5，栈:[5]
  读入4 → 栈:[5, 4]
  读入* → 弹出4和5，计算5*4=20，栈:[20]
  结果: 20
```

#### 解题思路

使用栈计算：
1. 遇到数字 → 入栈
2. 遇到运算符 → 弹出两个操作数计算，结果入栈

#### 代码实现

```cpp
int evalRPN(const vector<string>& tokens) {
    stack<int> stk;
    
    for (const string& token : tokens) {
        if (token == "+" || token == "-" || token == "*" || token == "/") {
            int b = stk.top(); stk.pop();
            int a = stk.top(); stk.pop();
            
            if (token == "+") stk.push(a + b);
            else if (token == "-") stk.push(a - b);
            else if (token == "*") stk.push(a * b);
            else stk.push(a / b);
        } else {
            stk.push(stoi(token));
        }
    }
    
    return stk.top();
}
```

同样地，RPN 求值器的接口接收 token 并返回结果，不负责命令行输入和展示。它应拒绝操作数不足、最终剩余多个值、非法数字 token 和除以 0；业务层捕获异常后再转换成面向用户的错误消息。这种分离让同一数据结构/算法既能服务命令行，也能被单元测试或其他模块复用。

还要单独处理**数值范围**：`std::stoi` 会拒绝超出 `int` 的输入 token，但如果直接用 `int` 做运算，加减乘溢出和 `INT_MIN / -1` 会产生未定义行为，不能把“机器上碰巧绕回去”当作结果。教程实现先把两个 `int` 操作数提升到 `std::int64_t` 完成计算，再检查结果能否放回 `int`；越界时抛出 `std::overflow_error`。这覆盖任意两个 `int` 的四则运算结果；若以后把输入也扩展到 64 位整数，则应使用更宽的受检运算或任意精度整数。上面的短代码只展示栈算法骨架，完整的语法与溢出检查以 `solution.cpp` 为准。

## 💡 本周总结

### 算法思想

1. **栈**：适合"最近的xxx"问题，如最近匹配、最近更大
2. **单调栈**：O(n)找下一个更大或更小元素
3. **队列**：适合"先来先服务"、层次遍历
4. **BFS**：无权/等权边最短步数、层级遍历的标准解法

### 编程技巧

1. **Lambda**：简洁的回调、自定义比较器
2. **显式捕获**：避免悬空引用和指针问题
3. **辅助栈/队列**：解决复杂问题
